# Requirement audit

This checklist is derived from the attached task, not from a reduced implementation target. The shipped content is one complete original level plus a separate proving ground; the architecture supports additional content and levels.

| Requested outcome | Implementation | Authoritative verification |
|---|---|---|
| Playful source-derived name, 50 candidates, random selection and two alphanumeric characters | The Gilded Goner → `TheGildedGoner-F3`; cryptographic random draw | `docs/TITLES.md` contains exactly 50 unique numbered titles; `src/identity.json` records choice 34 and suffix F3. |
| Initialize Git, project files, tools and public repository | Git main branch, npm lockfile, scripts, CI, public GitHub origin | Repository metadata identifies `michaelcrosato/TheGildedGoner-F3` with `private: false`; final source is pushed to main. |
| Use the specified game engine as the foundation | Full my-3d2dge 0.46.1, pinned commit and retained license, documented Canvas patches | Tests assert actual `Body`, `Attack`, `TileMap`, `FlowField` instances. Browser runs use its fixed-step `Game`, renderer, rigs, input, particles and synth. |
| Original spiritual successor with a polished complete level | Bellwether Sanctum: interconnected routes, checkpoints, NPC quest, environmental story, equipment, shortcut, boss and ending | Authored `SANCTUM` data, complete simulation and browser attract runs, inspected world/menu/boss/ending images. No copied source-game art, music, map or character names. |
| Extensive systemic proving ground and expansion architecture | Shared deterministic simulation, content registries, event boundary, pure AI intents, generic story effects, level travel, world-local persistence and isolated trial | `ARCHITECTURE.md`; tests for cross-level travel through save validation, content-defined stories, and resettable trial encounters. |
| Core gameplay loops demonstrated | Stamina, chained/heavy melee, guard/parry/posture/riposte, dodge, lock-on, healing, bolt, echo, four normal enemy archetypes, phased boss and ring hazards | Focused rules tests plus whole-journey completion stats requiring melee, heavy attacks, parries, dodges, spells, summon and phase two. |
| Death/rest/progression loop | Dropped and recoverable embers, replacement on another death, checkpoint respawn, ordinary-enemy reset, permanent equipment/upgrades/gates/boss flags | Logic tests and browser death/recovery, upgrade spending, equipment changes and reload regression. |
| Ten-second autonomous title/menu attract loop, indefinitely repeating until any input | Physical idle clock, real pathfinding/combat pilot, six-second ending interlude, fresh-loop reset, normal death/respawn and stall watchdog | Real-time ten-second trigger check; two complete browser loops per engine and five repeated deterministic simulation journeys. Keyboard, mouse, gamepad axes/buttons and touch interrupt. |
| Controller-first ten-foot interface; secondary keyboard/mouse | Large focused menus, common action map, left stick/d-pad navigation, Cross/Enter and Circle/Escape, contextual HUD, journal, equipment, settings, pause on focus/controller loss | Browser standard-gamepad tests, including movement, R1, Options, d-pad, Cross, Circle and touchpad; keyboard tests and inspected 1080p/ultrawide screens. Physical-device limit is explicit. |
| No mobile movement controls; mobile primarily attract mode | Automatic spectator mode with only the menu button visible | WebKit phone test asserts hidden HUD/title/performance/demo labels, absence of action widgets, working settings and touch interruption. |
| Source-inspired atmosphere, animation and visible frame timer; 25-FPS average target | Original gold/green ruined sanctuary, dressed procedural rigs/capes, telegraphs, particles, synthesized audio, actual FPS/ms display | Visually inspected screenshots; real synth analyser; per-engine 1080p title/exploration/boss benchmark table in `VERIFICATION.md`. |
| Testing respects shared-machine priority | DOM-free tests first, standalone file headless checks next, then one loopback HTTP server on uncommon port | Test scripts and recorded commands. No headed browsers or public phone tunnel used; no unrelated servers/processes modified. |
| Source information in chat, README and HTML, separate from engine evaluation | Date, source, engine pin/link, environment, confirmed model attribution and unasserted effort | README source table, HTML source comment and visible About screen; separate `ENGINE-EVALUATION.md`; final user handoff repeats the requested reference information. |
| Durable handoff and usable distribution | Architecture/content documentation, reproducible commands, static site, standalone licensed HTML, CI verification and Pages deployment | Build artifact, repository files, passing workflow and published-page smoke check recorded at handoff. |

The detailed measured evidence and explicit physical-device/audio limitations are in `VERIFICATION.md`. The core rule set, content route, save lifecycle, gamepad navigation and attract loop all have direct executable evidence; screenshots alone are not used to claim gameplay completion.
